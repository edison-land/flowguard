# 单项与组合审查对比

对象：[dcccrypto/ai-saas-starter](https://github.com/dcccrypto/ai-saas-starter)，版本 `af3d199c848a405ac221524d09e12b3adcaa0968`。原项目自述为 portfolio demo。本次假定计划公开付费上线，不代表其真实部署存在漏洞。

| 项目 | ECC 单项 | FlowGuard 组合 |
|---|---|---|
| 实际模式 | 独立 Agent 先读取 ECC 并审查 | 同一审查者追加读取 FlowGuard、ECC、Excellence 及专科资源；ToB 原生不可用，独立 fallback |
| 已覆盖机制 | 并发额度、重复事件重置、数据库写错误；条件性角色问题 | 保留前述机制，新增 OAuth subject 与本地 UUID 映射假设 |
| 结论 | 45/100，假定付费上线为 Blocked | Advisory No-go；不生成伪精确综合分 |
| 额外价值 | 本地证据与修复建议 | 哈希/行号证据、动态问题轨迹、反证、路径可达性依赖、跨领域证据缺口及未知负责人 |
| 实际执行 | 静态审查 | 静态审查＋证据工具；没有执行三个原生插件 |

实际源码观察支持：额度更新依赖旧读数；成功付款通知路径无条件重置额度。并发和重放未执行。身份映射及 SDK 错误语义保留为假设，不能写成已复现缺陷。身份路径如不可达，额度风险可能在修复身份后才变为可达。

对比有局限：同一审查者顺序执行、组合获得额外时间，非盲测；单一小型仓库，没有等预算多次运行和真值集。不能据此推断召回率、误报率或因果提升，也不能断言 ECC 无法独立发现新增假设。后续应做等预算独立重复、多技术栈及负样本试验。
